APIG-35 governs the presentation layer of the APIG system. It establishes how the site looks, how users navigate it, what interface components are reusable, and how the visual identity is maintained consistently across all APIG properties. This specification covers presentation and navigation only. It does not define the underlying data model, investigative architecture, or AI operations.

## Branding

APIG maintains consistent use of its approved visual identity. Brand elements include the APIG name, logo, logo variations, wordmarks, icons, typography, and approved visual treatments. Brand assets are tracked through the asset registry (APIG-34).

- Current brand colors: Bubblegum pink (#E91E8C), black (#1A1A1A), white, with gold highlights
- Primary logo: APIG Logo (APIG-ASSET-BRAND-001). Used on all APIG properties except the news media section.
- News media logo: Pig Monster News Media Logo (APIG-ASSET-BRAND-002). Used on the Pig Monster News Media section.
- Logo usage rules: preserve correct proportions, appropriate sizing, adequate surrounding space, legibility, consistent placement, appropriate use on light and dark backgrounds

## Global Site Structure

The APIG website uses a consistent global layout including: header with APIG logo and primary navigation, main content area, contextual navigation, and footer with required legal or informational links. Global elements remain consistent unless a documented reason requires a different presentation.

## Navigation

Navigation allows users to understand where they are and how to reach related areas. It is based on the structure and function of the system, not arbitrary page organization.

Navigation types include:

- Primary site sections
- Secondary navigation
- Breadcrumbs
- Related-record navigation
- Contextual links
- Search
- Filters
- Pagination
- Back and return navigation
- Links between related entities

Navigation should make relationships discoverable without requiring users to understand the underlying database.

## Page Layout

Pages use a consistent structural hierarchy:

1. Site identification and global navigation
2. Page or record title
3. Relevant contextual information
4. Primary content
5. Related information or navigation where appropriate
6. Consistent supporting elements

Layout variations remain consistent with the overall design system.

## Entity and Record Presentation

Pages representing APIG entities use consistent layouts appropriate to the entity type. Layouts exist for:

- Person
- Position
- Office
- Agency
- Organization
- Meeting
- Document
- Article
- Location
- Source
- Investigation

The presentation layer makes important relationships and relevant source information accessible from the record without requiring navigation through unrelated pages.

## Responsive Design

The interface functions across desktop, laptop, tablet, and mobile devices. Navigation, logos, typography, tables, and other interface elements remain usable at smaller screen sizes.

## Accessibility

The interface supports accessible use including:

- Adequate text readability
- Logical heading hierarchy
- Keyboard-accessible navigation
- Meaningful link labels
- Appropriate alternative text for meaningful images
- Sufficient visual distinction between elements
- Consistent navigation behavior

## Reusable Components

Common elements are implemented as reusable components:

- Header
- Logo
- Navigation menu
- Footer
- Breadcrumbs
- Search interface
- Entity navigation
- Related-record links
- Alerts
- Buttons
- Cards
- Tables
- Filters

## Navigation and System Growth

The navigation architecture accommodates expansion: new jurisdictions, new entity types, new investigative areas, new services, and new public sections, all without fundamental redesign of the global navigation structure.

## Governance

Significant changes to global layout, branding, navigation architecture, or reusable interface components should be documented and reconciled with related APIG specifications before implementation.
