APIG operates a network of accounts, domains, hosting services, repositories, integrations, forms, webhooks, scripts, and workflows. The System Resources registry is the single source of truth for all of these operational assets. Both human administrators and AI agents use this registry to understand what APIG already has, where assets are located, and how they connect to one another.

<Warning>
  This registry never contains passwords, API keys, tokens, or authentication secrets. Asset records note that a credential is required and identify where an authorized operator can obtain it securely.
</Warning>

## Registry Principles

The asset registry follows four core rules derived from APIG-34:

<Steps>
  <Step title="Registry before creation">
    Before creating any new asset, AI agents and administrators must search this registry. Reuse existing assets when possible. Only create new assets when no suitable asset exists.
  </Step>
  <Step title="No secrets in the registry">
    Asset records include a credential reference field that notes where to find a secret, not the secret itself. All credentials belong in a separate secure credential management system.
  </Step>
  <Step title="Asset relationships are tracked">
    Assets are connected in chains. For example, a Tally form may trigger a webhook, which runs a Google Apps Script, which updates a workflow. These relationships are documented as part of each asset record.
  </Step>
  <Step title="Human authorization gates">
    The registry does not grant AI authority to create accounts, spend money, enter contracts, or disclose protected information. AI may propose, document, and track assets. Consequential actions require human review and authorization.
  </Step>
</Steps>

## How AI Uses This Registry

When an AI agent is assigned a task that involves APIG infrastructure, it must:

1. Read the relevant registry section to determine what already exists.
2. Identify dependencies before proposing any modification.
3. Reuse existing assets rather than creating duplicates.
4. Update registry records when authorized to create or change an asset.
5. Request human intervention when authorization or credentials are required.

If an asset is missing from the registry, the AI must flag it and propose an update rather than assume the asset does not exist.
