APIG-27 establishes how APIG builds, preserves, and hands off institutional knowledge. The core principle is persistence: knowledge lives in the resource library, not in transient AI conversations. Every AI agent begins with the Start Here document, and every important resource carries version history so that continuity survives across personnel and system changes.

## Persistent Institutional Knowledge

APIG's knowledge lives in the resource library, not in AI conversations. Conversations are temporary. The resource library is durable, searchable, and auditable.

<Note>
  If a fact matters beyond the current session, it belongs in the resource library. AI conversations are for processing, not for storage.
</Note>

## Start Here as Entry Point

Every AI agent begins with the Start Here document before reading other resources. This document provides orientation, scope, and navigation guidance. No separate master index is required: the Start Here document is the navigation point.

The Start Here document answers:

- What APIG is and what it does
- How the resource library is organized
- Which resources are authoritative for which topics
- How to interpret APIG conventions and terminology

## Categories of Resources

APIG maintains distinct categories. Mixing them creates confusion and undermines accountability.

| Category | Purpose | Example |
| --- | --- | --- |
| **Specifications** | Binding rules and architecture | APIG-26 (security architecture) |
| **Records** | Documented facts and events | Investigation timelines, meeting minutes |
| **Guidance** | Recommended practice | Research methodology guides |
| **Evidence** | Source material and raw inputs | Documents, transcripts, datasets |

Specifications are prescriptive. Records are documentary. Guidance is advisory. Evidence is foundational. Each category is stored and versioned according to its own requirements.

## Version Control

Important resources use version numbers. When a document is superseded, the previous version is preserved. Superseded versions remain accessible for audit and historical reference.

Versioning practices include:

- Sequential version numbers for specifications (APIG-26 v1, v2, etc.)
- Date stamps for records and evidence
- Clear marking of the current authoritative version
- Retention of superseded versions in an archive state

## Change Logs

Changes to important resources are recorded with date, reason, and authorizer. The change log answers why a resource changed, who approved the change, and when it took effect.

A complete change log entry contains:

- Date of change
- Nature of the change (addition, modification, removal)
- Reason for the change
- Authorizing party
- Reference to any related decisions or events

## AI Handoff Continuity

When a new AI takes over, it can reconstruct project state from the resource library. No project context is assumed to survive in a conversation thread. The resource library is the single source of truth for ongoing work.

<Tip>
  At the end of any significant session, ensure that decisions, findings, and next steps are written into the appropriate resource library document or record.
</Tip>

## Accountability Navigation Preserves Distinctions

Version history does not collapse the distinction between direct conduct and supervisory, oversight, or appointment relationships. A change log shows what was altered and who authorized it. It does not imply that every party in the version history shares responsibility for the content's subject matter.

Accountability for a document's content is separate from accountability for the events the document describes. APIG's versioning system preserves that separation.
