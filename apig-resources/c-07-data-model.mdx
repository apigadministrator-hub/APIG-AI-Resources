APIG-07 defines the complete entity and relationship data model underlying the APIG information system. Every significant piece of information is stored as a structured entity with a persistent ID, relationships to other entities, provenance, and verification status. The database is the source of truth — the website is the presentation layer over it.

## The Database Is Not the Website

```text
DATABASE
Structured entities with IDs, relationships, provenance, history
    ↓
PRESENTATION LAYER
The website renders database entities in human-readable form
    ↓
USER
Navigates relationships without seeing database structure
```

Changes to how information is presented do not change the underlying data. Changes to the underlying data require sourcing, verification, and records.

## Entity Types and Persistent IDs

| Entity | ID Format | Description |
| --- | --- | --- |
| Jurisdiction | JURIS-\[STATE\]-\[TYPE\]-\[ID\] | State, county, municipality, special district |
| Organization | ORG-\[ID\] | Agency, board, authority, nonprofit, company, civic group |
| Position | POS-\[ID\] | Formal role existing independently of its occupant |
| Person | PERSON-\[ID\] | Individual, stable across position and organization changes |
| Document | DOC-\[ID\] | Formal record, ordinance, resolution, filing, report |
| Meeting | MTG-\[ID\] | Formal or public meeting with associated records |
| Source | SRC-\[ID\] | Origin of information, with provenance and verification |
| Relationship | REL-\[ID\] | Explicit connection between any two entities |
| Claim | CLM-\[ID\] | A statement attributed to a source |
| Event | EVT-\[ID\] | A documented occurrence associated with entities |

## Relationship Structure

Relationships in APIG are first-class entities with their own attributes:

- Relationship ID
- Type (holds, belongs to, supervised by, appointed by, appeared in, attended, etc.)
- Source entity and target entity
- Effective start and end dates
- Source (what establishes this relationship)
- Verification status
- Historical flag
- Notes

Because relationships are explicit entities with dates, APIG can answer: "Who supervised this person between 2019 and 2022?" or "What organizations was this person connected to during this period?"

## Data Record Quality Standards

Every data record should document:

- What is being claimed
- Where the information came from (source)
- When the source was produced
- When APIG obtained the information
- Current verification status
- Any conflicts with other records
- Historical status where applicable

## Information Hierarchy

```text
VERIFIED FACT      Confirmed by authoritative evidence
SOURCE CLAIM       Attributed to a specific source, not independently verified
AI INFERENCE       Generated by AI analysis — must be labeled, not published as fact
UNKNOWN            No information available — preferred over invented data
HISTORICAL         Previously accurate, may have changed
CONFLICTING        Multiple incompatible claims from different sources
```

## Data Lineage

For every important record, APIG should be able to trace: who entered it, when it was entered, what source it came from, when it was last verified, who verified it, what changed, and when.

## Architecture Principles

1. Entity IDs are persistent and do not change when entity status changes
2. Historical information is preserved, not deleted
3. Relationships are explicitly typed, not inferred from proximity
4. Every claim is attributed to a source
5. Unknown is a valid and preferred value over fabrication
6. The database structure must support expansion to new jurisdictions without redesign
7. AI-generated content is always labeled and requires human review before publication
