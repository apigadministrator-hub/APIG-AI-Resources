The APIG Asset Registry is the central record of every operational asset APIG uses. Before creating any new account, service, integration, or external resource, AI and administrators must check this registry first.

## Registry Rules

1. **Check before creating.** Search the registry for existing assets before registering or creating anything new.
2. **Record everything.** Every account, host, repository, brand asset, domain, integration, form, webhook, script, and workflow must be recorded here.
3. **No secrets stored here.** Passwords, API keys, tokens, and other credentials are never stored in this registry.
4. **Human authorization required.** New accounts, spending, and contracts require explicit human administrator approval.

## Asset Status Values

| Status | Meaning |
| --- | --- |
| Active | Asset is in current use and fully operational. |
| Inactive | Asset is temporarily unused but retained for future needs. |
| Pending | Asset is registered but not yet provisioned or activated. |
| Unknown | Current status cannot be determined and requires review. |
| Deprecated | Asset is scheduled for retirement or replacement. |
| Archived | Asset is retired and kept for historical reference only. |

## Asset ID Format

Every asset is assigned a unique identifier in this format:

```text
APIG-ASSET-[TYPE]-[NUMBER]
```

- `APIG-ASSET` is the fixed prefix.
- `[TYPE]` is a three-letter code for the asset category.
- `[NUMBER]` is a zero-padded sequential number.

### Asset Type Codes

| Code | Category |
| --- | --- |
| ACCT | Account |
| HOST | Hosting |
| REPO | Repository |
| BRAND | Brand asset |
| DOM | Domain |
| INTG | Integration |
| FORM | Form |
| HOOK | Webhook |
| SCRP | Script |
| WKFL | Workflow |
